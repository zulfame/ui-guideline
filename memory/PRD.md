# PRD — UI Guidelines / Design System Template

## Problem Statement
Membangun template **UI Guidelines / Design System** generik sebagai fondasi aplikasi enterprise masa depan.
- 100% komponen resmi shadcn/ui (tidak ada primitive custom kecuali disetujui).
- Placeholder generik ("Application Name", "Feature One"), TANPA logika bisnis spesifik.
- Gaya visual monochrome-first, minimal, modern enterprise.
- Font: Geist (primary). Ikon: lucide-react saja.
- Reusable patterns, compact design (grid 4px), design tokens (HSL).

**Bahasa komunikasi: Indonesia (Bahasa Indonesia).**

## Arsitektur (Frontend-only)
- `/app/frontend/docs/DESIGN_SYSTEM.md` & `DESIGN_SYSTEM_RULES.md` — SSOT aturan UI (termasuk R38).
- `src/components/composite/` — PasswordInput, Autocomplete, Kanban, DataGrid, CodeBlock, dll.
- `src/components/ui/` — Shadcn primitives (dimodifikasi untuk compact UI).
- `src/config/` — navigation.js, componentPreviews.jsx, compositePreviews.jsx.
- `src/pages/layouts/` — DataTableLayoutPage, FormElementsPage, FormLayoutPage.
- `src/pages/ComponentsPage.jsx` — data table gabungan Base + Composite (A-Z).

## Rule Kunci
- **R38**: Modifikasi primitive/composite harus jaga compact spacing (`px-6 py-4`), grid 4px, token monochrome (`border-border`), typography tepat. Verifikasi semua consumer via screenshot sebelum selesai.

- (2026-08-02) **API Auth Mobile (JWT) — paritas collection Postman "JWT Mobile" (Flutter)** [FEATURE/AUTH]: modul baru `backend/routes_mobile_auth.py` (pola `from server import ...`, route register saat import di server.py sebelum `include_router`; 4 path ditambah ke `_PUBLIC_API_PATHS` agar bypass middleware admin & divalidasi sendiri). Endpoint:
  - **POST `/api/jwt-auth`** — login. Body `{username, password, device_identifier, device_name, device_os, fmc_token}`. `username` menerima **email/username/phone** (pakai `$or`). Sukses → `{"success":true,"data":{"token_type":"bearer","expires_in":3600,"access_token":"<jwt>"}}`. Token JWT HS256 `type:"mobile"` berisi `jti`+`did` (device), TTL `MOBILE_JWT_EXPIRY_SECONDS` (3600). **Single-device binding**: bila akun sudah terikat perangkat lain → 401 `{"success":false,"message":"Akun sudah terhubungan dengan perangkat lain"}`; kredensial salah → 401 `"Kredensial yang Anda masukkan tidak sesuai"`; brute-force throttle (reuse helper web) → 429. Binding disimpan di `users.mobile_device{device_identifier,device_name,device_os,fcm_token,jti,bound_at}` + mirror ke field device_* top-level.
  - **GET `/api/jwt-me`** — profil: `{success,data:{user:{id(=user_id),name,username,email,role,office,alias,mso_code,collector_code,is_active}, office:{code,name,address,telephone,longitude,latitude,radius,coa}, device:{device_identifier,device_name,device_os,fmc_token}}}`. Validasi jti harus cocok dengan binding aktif (token pasca-logout ditolak). ⚠️ **`office.coa` diambil dari field `note` Office** (COA disimpan di kolom Note Office).
  - **POST `/api/jwt-refresh`** — terbitkan access token baru (boleh dari token kedaluwarsa selama dalam window `MOBILE_JWT_REFRESH_DAYS`=30 & jti masih terikat).
  - **POST `/api/jwt-logout`** — unbind device (`$unset mobile_device`) → token lama tak berlaku lagi di /jwt-me.
  - Diverifikasi via curl end-to-end: login(A)→me→refresh→login(B) konflik 401→logout→me 401→login(B) sukses (via email)→wrong-cred 401→cleanup. Semua sesuai kontrak. Env baru: `MOBILE_JWT_EXPIRY_SECONDS`, `MOBILE_JWT_REFRESH_DAYS`.
